01 · Kerwin 导语

这不是一份“AI 比人便宜多少”的小账，而是数字劳动第一次可以被逐层计量

这次服务器审计很小，却给了 Agent Economy 一个难得的真实样本：我们第一次可以把一项完整专业任务，从模型调用、上下文读取、Token 成本，一直映射到人类等价工时和实际修复结果。真正重要的不是“¥19.4”这个数字本身，而是这条链条开始可测量：Compute → Token → Agent Runtime → Correct Task → Human Hours Saved → Economic Value。

实际成本约 ¥19.4按原报告价格来源最接近的 OpenRouter / GMICloud MiMo 30% 折扣路由重算，缓存并非免费。
上下文才是大头缓存读取占全部输入 Token 的约 87.6%；总 Prompt Read / Output 约 305:1。
缓存就是经济变量若相同输入全部按 cache miss 计价，MiMo 折扣路由成本约从 $2.69 升到 $19.50，约 7.24 倍。
下一步看 $/Correct Task模型单价已很低，真正决定经济价值的是完成率、返工率、人类复核量和可并行复制规模。
02 · Audit Task

第一部分：审计任务与目标

任务是什么？

简单来说，就是给一台服务器做“全身体检”。

这台服务器位于新加坡（DigitalOcean），运行着一套 AI Agent 系统——可以理解为 4 个“AI 员工”24 小时在这台机器上工作，分别负责任务执行、投资研究审核、运维执行和客户服务。

审计要做的事情包括：

查硬件：CPU 够不够用、内存有没有爆、硬盘还剩多少；查安全：服务器密码登录是否暴露在公网、防火墙有没有开、网站有没有设访问密码；查软件：AI 系统版本是不是最新的、配置有没有矛盾、后台有没有多余服务；查模型：4 个 AI 员工的模型配置是否正确、有没有互相冲突；发现问题并修复：能当场修的直接修，不能修的记录下来。

审计耗时（含等待）约 11 小时
AI 交互轮次52 轮
发现问题数14 项（2 红 / 4 橙 / 8 黄）
当场修复数11 项

03 · Token Ledger

第二部分：AI 处理成本与 Token 账本

(a) 调用情况

按原报告统计，本次审计由 AI Agent 自主完成，共记录 52 轮 AI 交互。这里沿用原报告口径，不重新推翻或重算调用次数。

(b) Token 消耗明细

指标数量说明
新增输入 Token7,909,718每轮调用中新产生的输入
缓存读取 Token55,700,736命中 Prompt / KV Cache 的已计算上下文
输出 Token208,488模型生成的回复内容
推理 Token98,122沿用原报告原始 usage 字段；是否已包含在 output breakdown 中取决于具体 provider 口径
总计费 Token63,818,942按原报告：新增输入 + 缓存读取 + 输出
87.6%缓存读取占全部输入 Token 的比例
38:1Fresh Input / Output
305:1Total Prompt Read / Output

为什么输入远大于输出？

Agent 在长任务里会不断携带历史上下文、服务器状态、工具定义和此前结果。原报告中的“38:1”是 新增输入 / 输出；如果把缓存读取也算入模型反复读取的上下文，总 Prompt Read / Output 约为 305:1。这更能反映长程 Agent 的真实工作结构。

缓存机制的价值

缓存不是把 Token“变没”，而是让大量重复上下文从昂贵的 cache miss 变成低价 cache read。也就是说，Agent 的经济性不仅由模型能力决定，还由上下文复用、缓存命中率、路由和记忆系统决定。

04 · Pricing Correction

第三部分：价格修正与三模型横向比较

(a) 本次 MiMo 实际执行成本代理

原报告采用的 MiMo 输入 / 输出价格约为 $0.304 / $0.609 每百万 Token。公开价格核验显示，这与 OpenRouter 上 GMICloud 的 MiMo‑V2.5‑Pro 30% 折扣路由基本一致；该路由的 cache read 并非免费，而是约 $0.0028/M。

(b) 按各官方模型页当前价格横向比较

这直接修正原报告最明显的错误：GPT‑5.6 Luna 的 cached input 不是 $0.50/M；按 OpenAI 当前模型页的文本 Token 价格，固定同一 Token workload 的理论成本约 $2.95，并非 $29.68。原报告“GPT 比 MiMo 贵 11.7 倍”的结论不成立。

重要边界：这里比较的是“同一组 Token 数量按不同单价重算”。不同模型真正执行同一任务时，可能产生不同的调用轮次、上下文长度、输出量、推理量和成功率，因此不能把这张表称作真实 A/B 实测。

06 · Corrected Economics

第五部分：修正后的 Agent 经济效率

AI Agent（MiMo 折扣路由）人类工程师（初级）人类工程师（高级）
完成时间11 小时（含等待）3–4 小时3–4 小时
AI 纯执行时间~2 小时（原报告估算）——
直接成本约 ¥19.4约 ¥204约 ¥1,200–3,200
人工成本 / AI 成本基准约 10.5×约 62–165×

1. 成本维度

按最接近原报告定价来源的 MiMo 折扣路由，本次模型 Token 成本约为初级人工 4 小时工资基准的 1/10.5，高级 DevOps / 安全顾问基准的约 1/62 至 1/165。这仍然显示出显著的数字劳动成本优势。

2. 时间维度

Agent 的墙钟时间更长（11 小时 vs 3–4 小时），说明成本优势不等于延迟优势。但 Agent 可以夜间运行、并行复制，而且人机等待并不等于持续占用人类工时。后续应分别记录 Wall-clock Time、Machine Active Time 与 Human-in-the-loop Time。

3. 质量维度

本次 Agent 发现 14 项问题、当场修复 11 项，这是有价值的任务结果；但仅凭这一组数据，不能严谨证明“发现问题能力不亚于初级工程师”。真正的质量比较应让独立 DevOps 对同一服务器盲审，再比较 Precision、Recall、Severity、Fix Correctness 和返工率。

4. 边际成本维度

“Agent 边际成本趋近于零”应修正。第 1 次审计约 ¥19，第 100 次如果工作量相同仍要消耗约 100 份推理成本。真正被压低的是数字劳动力的复制、招聘、培训、排班和组织成本；人工工资被转换成一个低得多、可弹性扩缩的 Compute / Token 变量成本。

07 · What This Small Audit Reveals

这个小小的审计任务，实际上反映出六个更大的结论

① Token 已经可以开始映射为“数字劳动”

63.8M 计费 Token 不再只是 API 用量，而是完成了一个可描述、可验收的专业任务：服务器体检、14 项问题识别、11 项修复和一份报告。于是 Token 可以继续往下映射到任务产出和人类等价工时。

② Agent 时代，真正昂贵的往往不是“说话”，而是“记住并反复理解工作现场”

输出只有 208K Token，但总输入读取约 63.61M Token；其中 87.6% 是缓存读取。Agent 的工作形态更像一个工程师不断翻阅日志、配置、历史判断和工具状态，再做少量行动。因此 Memory、KV Cache、Context Routing、Storage 和网络不是外围成本，而是 Agent 生产函数的一部分。

③ Cache 从技术优化变成了劳动经济学变量

同样一组 workload，MiMo 折扣路由如果没有缓存价格优势，理论费用会从约 $2.69 变成约 $19.50。也就是说，缓存机制本身就能制造约 7 倍的“数字劳动成本差”。这与我们此前研究 Dynamo / KV Cache 的结论直接接上。

④ 模型 Token 单价正在低到不再是唯一核心矛盾

按当前定价，同样 workload 的三个模型都只是几美元量级。下一阶段企业不会只问“哪个模型每百万 Token 更便宜”，而会问：谁的 $/Correct Task 更低、谁需要更少返工、谁能处理更长任务、谁能减少人类复核。

⑤ Agent 的乘数效应来自可复制与可并行，而不是单次任务一定更快

这次案例里 Agent 墙钟时间甚至比人类估算更长。Agent 的真正优势是：同一套流程可以复制到 10 台、100 台、1,000 台服务器，夜间运行且不需要招聘同等数量的人。规模化以后，“每个 Agent 工时能管理多少真实工作对象”才是关键。

⑥ 最终不能停在 Token，要落到经济价值

Agent Economy 的计量链

MW / Compute → Tokens → Agent Runtime → Correct Tasks → Net Human Hours Saved → $ Economic Output → ROIC

这次服务器审计可以作为 Sample #1：我们已经拥有 Token、推理成本、任务结果和人类工时估算。下一步要补齐的是“质量校验”和“任务经济价值”，最终形成 $/Correct Task、$/Human Hour Saved、Economic Value / Agent Hour。
