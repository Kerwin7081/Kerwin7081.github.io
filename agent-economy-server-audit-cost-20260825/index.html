一次 OpenClaw 云服务器全面审计，把抽象的 Token 变成了一笔可核算的“数字劳动账”：52 轮交互、63.8M（百万）计费 Token、14 项问题识别、11 项修复。按任务所对应的 MiMo 海外第三方折扣路由映射，模型调用直接成本约 ¥19.4；若换成人类工程师完成同类工作，估算需要 3.5–4 小时。更重要的是，这个案例把 Agent 的工作结构、Prompt Cache、KV Cache 与 HBM / DRAM / NAND 的价值第一次具象地连在了一起。

01 · KERWIN 导语

如何具象地理解：一个工作任务通过 Agent 到底要花多少钱？

讨论 Agent 经济性时，“每百万 Token 多少钱”仍然太抽象。更直观的问题是：完成一项真实工作，Agent 到底花多少钱？如果换成人来做，需要多少工时、对应多少工资？

2026 年初，Kerwin 搭建了 OpenClaw，并长期运行在云服务器上。半年多持续使用后，Agent、模型配置、后台服务、日志、缓存与各种依赖不断累积，系统逐渐臃肿，也开始出现安全、资源占用和配置管理问题。于是 Kerwin 下达了一个具体指令：对整台服务器做一次全面审计，发现问题、能修的直接修，并形成完整报告。

这不是问答，也不是生成一段文字，而是一项可以验收的专业工作：读取服务器状态、理解配置、调用工具、判断问题、执行修复、再次验证并形成报告。它因此提供了一个很少见的真实样本，让我们可以沿着同一条链条去计量：

Compute → Tokens → Agent Runtime → Correct Tasks → Human Hours Saved → Economic Value

这篇文章真正想回答的不是“AI 一定比人便宜多少倍”，而是更基础的问题：当 Agent 开始真正替人工作以后，一份数字劳动应该怎样计价？

这揭示了 Agent 与“普通聊天”不同的工作形态

长程 Agent 每一步都要携带大量工作现场：System Prompt、工具定义、历史对话、文件、代码、日志、服务器状态、前一步工具结果。真正输出的动作可能很短，但在行动前需要反复“读工作现场”。因此，长程 Coding / Research / Ops Agent 往往天然偏向 Input-heavy 与 Cache-heavy。

04 · PROMPT CACHE → KV CACHE → MEMORY

第三部分：55.7M（百万）缓存读取，如何把 Token 账单连接到 HBM？

先分清两层：Prompt Cache 与 KV Cache 不是同一件事

Prompt Cache 是客户账单层。重复前缀命中缓存后，Provider 不再按完整新输入价格收费；55.7M（百万）Token 没有消失，只是变成更便宜的 cached input。

KV Cache 是推理物理层。模型在生成过程中保存已经计算过的 Key / Value 注意力状态，避免每生成一个新 Token 都把全部历史重新计算。活跃 KV 对带宽极其敏感，通常优先驻留 GPU 显存 / HBM；容量扩大后，可以向 CPU DRAM、SSD / NAND、远程存储分层。

这个案例为什么能让客户理解“存储值多少钱”

按本任务 MiMo GMICloud 折扣路由，模型调用成本约 $2.69。如果把 55.7M 缓存读取全部假设成新的 cache miss，费用会升至约 $19.50，即 7.24×。换句话说，在这个账单情景里，Prompt Cache 把模型费用压低了约 86%。

这不是说“HBM 让账单直接便宜 86%”，而是说明：上下文能否被高效保存、搬运和复用，已经直接影响 Agent 的单位劳动成本。

HBM、DRAM、NAND 分别在做什么？

HBM更像 Agent 的“高速工作记忆”：离 GPU 最近、带宽最高、最贵，适合活跃 KV 与高频访问状态；服务器 DRAM承接更大但相对不那么热的上下文；SSD / NAND则提供更廉价的大容量缓存与持久层。随着 Agent 数量、上下文长度和并发任务增加，这三层共同组成“机器记忆层级”。

这也是理解三星电子、SK 海力士、美光等存储公司的一个具象例子。但需求关系不能简单写成“Agent 越多，HBM 一定同比例增加”，因为模型架构同时在快速压缩 KV。

Memory Demand ∝ Agent Runtime × Context Length × Concurrency ÷ KV Compression Efficiency

为什么有些中国模型的 Cache Price 特别低？答案不是“HBM 更便宜”

公开资料能确认两类真实技术因素。第一，DeepSeek 的 MLA 架构显著压缩上下文 KV Cache，使其可以把可复用上下文放到低成本分布式硬盘；DeepSeek 官方 Context Caching on Disk 就是这一思路。第二，小米 MiMo V2.5 的 Hybrid Sliding Window Attention 把 KV Cache 存储降到 Full Attention 的约 1/7；其基于 SGLang HiCache 的多级缓存优化，又把 GPU 显存、CPU 内存与 SSD 之间的数据搬运量降到优化前的近 1/7，并把可缓存 Token 数提高到近 5 倍。

但这些技术事实仍然不能解释全部 API 价格差。最有力的反证就是：同一个模型，在不同 Provider 的 Cache Read 报价可以相差几十倍。

05 · MODEL PRICING & INFRASTRUCTURE

第四部分：这 63.8M（百万）Token 到底多少钱？怎样才算公平比较中美模型？

先看本任务：实际对应的 MiMo 价格映射

本任务账本的 MiMo 单价与 OpenRouter 上 GMICloud 的 MiMo V2.5 Pro 折扣路由一致：Fresh Input $0.3045 / M、Cache Read $0.0028 / M、Output $0.609 / M。

官方国际价格：Luna 确实更低，但只是在这一 Token mix 下

MiMo V2.5 Pro · 小米海外官方$0.435$0.0036$0.87$3.82

按这张官方价格表，Luna 的 $2.95 是 MiMo / DeepSeek $3.82 的约 77%，也就是低约 23%，并不是 60%。优势主要来自 Fresh Input：Luna 新输入价 $0.20，仅为 $0.435 的约 46%；但它的 Cached Input 与 Output 都更贵。

更进一步，把 MiMo 与 Luna 的价格写成 Token mix，就得到一个很实用的分界线：

Luna 更便宜 ⇔ 0.0164 × Cache + 0.33 × Output < 0.235 × Fresh Input

在本任务 Output / Fresh Input 仅约 2.64% 的情况下，只要 Cache / Fresh Input 低于约 13.8×，Luna 的官方标价就更便宜；本任务实际是 7.04×，所以 Luna 在官方价口径下胜出。若完全没有 Cache，仅比较 Fresh Input 与 Output，则当 Output / Input 超过约 71% 时，MiMo 的低 Output 价格会开始更有优势。

所以不能推演成“美国模型天然更适合 Agent”。正确说法是：Luna 当前价格结构偏向 Fresh-Input-heavy、Output-light 的任务；中国模型当前极低的 Cache 价格则更适合重复上下文非常高的 workload。哪一种更便宜，取决于 Fresh / Cache / Output 的组合，而不是国别。

中国国内价、海外官方价、海外第三方托管价必须分开

小米官方明确区分 Domestic 与 Overseas 计费，并向 Token Plan 提供中国、新加坡、欧洲不同集群与独立 Base URL，这意味着 MiMo 至少可以明确验证存在分区服务体系。MiMo V2.5 Pro 国内价格为 Cache Hit ¥0.025、Cache Miss ¥3、Output ¥6 / M；海外价格为 $0.0036、$0.435、$0.87 / M。

DeepSeek 则不同：虽然官方英文页面给出美元价格，但 OpenRouter 当前把 DeepSeek 官方 Provider 标记为 China。因此 DeepSeek 的官方美元价不能被当成已经证明的“海外物理托管成本”。这也是前面对“中美价格趋同”需要修正的地方。

更干净的比较方法：Same Model / Different Provider；Same Provider / Different Model

如果目的是研究“模型算法效率”和“海外基础设施成本”分别贡献多少，最有价值的不是简单比较 China API vs US API，而是做两个控制变量实验：

实验控制什么能回答什么
Same Model / Different Provider固定模型Provider 基础设施、推理栈、利用率与商业定价差异
Same Provider / Different Model尽量固定 Provider模型架构与部署效率差异

以 OpenRouter 2026-08-25 快照为例，GMICloud 被列为美国 Provider。当前促销价下，同一份 Token workload：MiMo V2.5 Pro 约 $2.69，DeepSeek V4 Pro 约 $8.57。这说明“同为中国模型”也不存在统一的海外推理价格。

但这仍然不是严格的硬件成本实验。OpenRouter 展示的是 Provider / Headquarters 与终端报价，不披露每个请求实际 GPU 型号、数据中心地点、量化、批处理、利用率与服务等级；促销也会变化。因此这张表只能作为“海外 Provider 价格代理”，不能直接等同于真实数据中心 BOM / 电力成本。

最终应该比较的不是 $/M Token，而是 $/Correct Task

GPT-5.6 Luna 是 OpenAI 的 cost-sensitive tier，而 MiMo V2.5 Pro / DeepSeek V4 Pro 是各自更高定位的 Pro 模型。即使 Token 单价算得完全正确，如果模型完成率、调用轮次、返工次数不同，真实任务成本仍可能完全相反。

$/Correct Task = Token Mix Cost + Tool / Runtime + Rework + Human Review

因此本文的跨模型表只回答价格结构，不回答同等质量下谁真正更便宜。要回答后者，必须让不同模型分别独立完成同一服务器审计，再比较任务成功率、总 Token、工具调用、返工与人工复核。

07 · WHAT THIS REVEALS

这个小任务，最终反映出七个更大的结论

① Token 开始可以映射为“数字劳动”

63.8M（百万）计费 Token 不再只是 API 用量，而是完成了一个可描述、可验收的专业任务。于是 Token 可以继续映射到任务、人类等价工时与经济价值。

② 长程 Agent 的核心成本越来越像“阅读工作现场”

本任务输出只有 208K Token，总 Prompt Read 却约 63.61M（百万）。Agent 经济性因此越来越由 Fresh Input、Cache hit、Context Routing 与 Tool loop 决定，而不是只看输出。

③ Cache 从工程优化变成劳动经济学变量

本案例账单情景中，Prompt Cache 使费用从假设的 $19.50 降到约 $2.69。重复上下文的复用率会直接改变数字劳动的单位成本。

④ HBM / DRAM / NAND 是 Agent“机器记忆”层级，但效率也在快速提高

Agent 扩张会增加上下文与并发状态需求；与此同时 MLA、SWA、KV Compression 与分层缓存不断降低单位 Token 的内存占用。因此存储投资逻辑应该看总 Agent 工作量增长是否持续快于每 Token Memory Footprint 的下降。

⑤ “中国模型 vs 美国模型”不能只看国别价格

官方价、国内价、海外区域价、第三方 Provider 价属于不同成本层。相同模型换 Provider 后价格可以显著变化；同一 Provider 上不同模型也可能差异巨大。真正应拆的是 Architecture、Inference Stack、Infrastructure 与 Commercial Pricing。

⑥ 模型的最佳价格结构取决于 Token Mix

Fresh-input-heavy、Output-light 的任务会更偏爱低 Input 价；极高重复上下文的任务更看重 Cache Read；写作和一次性问答则更看重 Output。Agent 时代需要从“$/M Token”升级到Token Mix Pricing。

⑦ 最终不能停在 Token

Agent Economy 的最终计量链

MW / Compute → Tokens → Agent Runtime → Correct Tasks → Net Human Hours Saved → $ Economic Output → ROIC

这次服务器审计可以作为 Sample #1。下一步真正需要补齐的是不同模型的同任务盲测、质量因子、人类监督时间与任务经济价值，最终把指标落到 $/Correct Task、$/Human Hour Saved、Economic Value / Agent Hour。
