01 · KERWIN 导语

1MW、1GW、多少张 GPU、多少资本支出、多少收入——这笔账大概怎么框算？

AI 基础设施新闻里的数字一直是散落的。1MW、1GW、5万张 GPU（图形处理器）、几十亿美元 Capex（资本支出）、几十亿美元 ARR（年化经常性收入）……单看都很大，却很难形成坐标系。

我们从 IREN 的真实合同出发，建立固定换算链：Gross Power（总电力容量）→ PUE（电力使用效率）→ IT Load（IT负载）→ GPU（图形处理器）→ HBM（高带宽内存）/LPDDR（低功耗内存）/NAND（闪存）BOM（物料清单）→ GPUh（每GPU小时）/ Token Revenue（Token收入）→ Capex（资本支出）→ 回本期。

目标不是追求小数点，而是以后研究 IREN、CoreWeave、Nebius、Oracle、SpaceX 或 Hyperscaler（超大规模云厂商）时，先在几十秒内判断数量级是否合理。

06 · MEMORY BOM

把1MW / 1GW IT Load（IT负载）拆成两代 Memory BOM（内存与存储物料）

1MW IT 工作中枢GB300（Blackwell Ultra）Vera Rubin投资含义
GPU数量≈500≈500*Rubin核心不是简单多塞GPU，而是同一MW产出更多Token。
HBM（高带宽内存）容量≈144TB HBM3E≈144TB HBM4容量相同；Rubin升级带宽、工艺与单价。
CPU侧内存≈125TB LPDDR5≈375TB LPDDR5XVera CPU使Rubin的CPU内存含量显著增加。
本地NAND（闪存）≈4.25PB≈4.25PB floor（下限）*Rubin共享KV Cache（键值缓存）层未完全计入。
Memory BOM美元值——上游经济含量代理，不等于内存厂商最终确认收入。
* Rubin口径：官方已披露288GB HBM4/GPU、22TB/s HBM带宽和整架54TB LPDDR5X；完整本地/共享存储、整架可比功耗与市场采购价仍需持续校准。

为什么用内存厂商财报校准，而不直接拿财报收入除以GW？

硬件规格回答“物理上需要多少内存”，内存厂商财报回答“价格和需求环境是否支持这套BOM价值”。三星、SK hynix（SK海力士）与 Micron（美光）的披露共同指向：AI需求已经从 HBM（高带宽内存）扩散到 server DRAM（服务器动态随机存取内存）、LPDDR（低功耗内存）与 eSSD（企业级固态硬盘）/NAND（闪存）。因此财报用于校准价格周期与价值池，而不是硬凑“1GW=某家公司多少收入”。

07 · REAL-WORLD ANCHORS

真实合同和硬件披露，是这套模型不断收敛的校准样本

Microsoft × IREN≈$9.7MARR / MW IT / 年：$9.7B、5年、200MW critical IT load（关键IT负载），满负荷约$1.94B年化。
GB300 InferenceX2.8Mtokens/s/MW；特定低延迟推理基准，用于单位电力Token产能现实锚。
Vera RubinBase 3×模型只用3× GB300作为基础情景；官方特定模型对Grace Blackwell/GB200的上锚更高。
IREN带来的方法论：持续跟踪 Secured Power（已锁定电力）→ Energized Power（已通电）→ IT Load（IT负载）→ GPU Installed（GPU已安装）→ Contracted Capacity（已签约容量）→ Revenue-Producing Capacity（产生收入容量）的逐层转化，而不是只看“宣布多少GW”。
